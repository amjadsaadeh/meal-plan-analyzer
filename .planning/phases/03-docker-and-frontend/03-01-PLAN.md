<task type="auto">
  <name>Task 1: Add redis service, worker service, and media_files volume to docker-compose.yml</name>
  <files>docker-compose.yml</files>
  <action>
Read the current docker-compose.yml first (it has `db` and `web` services only, and a `postgres_data` volume).

Make these changes:

1. Add `redis` service before `web`:
```yaml
  redis:
    image: redis:7-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
```

2. Add `worker` service after `web`:
```yaml
  worker:
    build: .
    command: >
      celery -A config worker
        --loglevel=info
        --concurrency=2
        --max-tasks-per-child=50
    volumes:
      - media_files:/app/media
    environment:
      - SECRET_KEY=${SECRET_KEY:-change-me-generate-a-real-key-for-production}
      - DEBUG=True
      - DATABASE_URL=postgres://mealplanner:mealplanner@db:5432/mealplanner
      - CELERY_BROKER_URL=redis://redis:6379/0
      - REDIS_URL=redis://redis:6379/1
      - SITE_BASE_URL=http://web:8000
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
```

Critical: worker does NOT mount `- .:/app`. Only `media_files:/app/media`. The Dockerfile bakes in all application code. The `.:/app` bind-mount is only needed in `web` for live-reload during local development.

Also critical: `SITE_BASE_URL=http://web:8000` uses the Docker internal service name `web`, not `localhost`. Inside Docker, `localhost` resolves to the worker container itself.

3. Update the `web` service:
   - Add to its `volumes:` section: `- media_files:/app/media`
   - Add to its `environment:` section:
     - `- CELERY_BROKER_URL=redis://redis:6379/0`
     - `- REDIS_URL=redis://redis:6379/1`
     - `- SITE_BASE_URL=http://web:8000`
   - Add to its `depends_on:` block:
     ```yaml
       redis:
         condition: service_healthy
     ```

4. Add `media_files:` to the top-level `volumes:` block (alongside `postgres_data:`):
```yaml
volumes:
  postgres_data:
  media_files:
```

The `--max-tasks-per-child=50` on the CLI duplicates `CELERY_WORKER_MAX_TASKS_PER_CHILD=50` already in settings.py (set in Phase 1), but the explicit CLI flag makes the intent visible in the compose file. Both are fine together.
