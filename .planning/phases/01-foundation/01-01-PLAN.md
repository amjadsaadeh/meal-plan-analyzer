       ```python
       import os
       from celery import Celery

       os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings")

       app = Celery("meal_plan_analyzer")
       app.config_from_object("django.conf:settings", namespace="CELERY")
       app.autodiscover_tasks()
       ```

       This import is MANDATORY — without it Django's module system never loads config.celery and

       ```python
       from .celery import app as celery_app

       __all__ = ("celery_app",)
       ```

       ```
       # WeasyPrint base URL (used by Celery worker — no request context available)

       ```
       Place this section after the existing DATABASE_URL entry.

<task type="auto">
  <name>Task 2: Add Celery settings block, Redis cache backend, and SITE_BASE_URL to settings.py</name>
  <files>
    config/settings.py
  </files>
  <action>
    Add the following blocks to config/settings.py. Read the file first to find the correct insertion point — add after the existing CACHES entry (if any) or after the DATABASES block. The existing settings.py has no CACHES block (Django default LocMemCache is in effect implicitly), so this is a pure addition.

    Append this Celery settings block:
    ```python
    # --- Celery ---
    CELERY_BROKER_URL = env("CELERY_BROKER_URL", default="redis://localhost:6379/0")
    CELERY_RESULT_BACKEND = None  # BackgroundJob model is the source of truth; no Celery result backend needed
    CELERY_TASK_SERIALIZER = "json"
    CELERY_RESULT_SERIALIZER = "json"
    CELERY_ACCEPT_CONTENT = ["json"]
    CELERY_TASK_TRACK_STARTED = True
    CELERY_WORKER_PREFETCH_MULTIPLIER = 1  # prevents long tasks from starving the queue
    CELERY_WORKER_MAX_TASKS_PER_CHILD = 50  # TASK-04: WeasyPrint CFFI memory leak mitigation
    CELERY_WORKER_MAX_MEMORY_PER_CHILD = 200_000  # 200 MB safety net (in KB)
    CELERY_TIMEZONE = "UTC"
    CELERY_ENABLE_UTC = True

    # --- Django cache (Redis replaces LocMemCache so alias cache is shared across workers) ---
    # Use db/1 to isolate cache from Celery broker on db/0 — prevents key collisions
    CACHES = {
        "default": {
            "BACKEND": "django.core.cache.backends.redis.RedisCache",
            "LOCATION": env("REDIS_URL", default="redis://localhost:6379/1"),
        }
    }

    # --- WeasyPrint worker context ---
    # The Celery worker has no HTTP request; base_url must be an absolute URL from settings
    SITE_BASE_URL = env("SITE_BASE_URL", default="http://localhost:8000")
    ```

    Important notes:
    - Do NOT add django-celery-results or set CELERY_RESULT_BACKEND to anything other than None.
      The BackgroundJob model is the sole source of truth per the architectural decision in STATE.md.
    - Do NOT add "django_celery_results" to INSTALLED_APPS — it is not installed.
    - CELERY_WORKER_MAX_TASKS_PER_CHILD maps to Celery's worker_max_tasks_per_child via the
      namespace="CELERY" stripping. This is the correct key name (not WORKER_MAX_TASKS_PER_CHILD).
    - Use db/0 for CELERY_BROKER_URL and db/1 for REDIS_URL cache LOCATION — never the same db index.
    - Format the file with black after editing: uv run black config/settings.py
  </action>
