  <action>
Create `deployment/app-deployment/k8s/base/redis.yaml` containing two resources separated by `---`:

**Resource 1: Redis Deployment**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
spec:
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7-alpine
          ports:
            - containerPort: 6379
          livenessProbe:
            exec:
              command: ["redis-cli", "ping"]
            initialDelaySeconds: 15
            periodSeconds: 10
          readinessProbe:
            exec:
              command: ["redis-cli", "ping"]
            initialDelaySeconds: 5
            periodSeconds: 5
```

**Resource 2: Redis Service**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: redis
spec:
  type: ClusterIP
  selector:
    app: redis
  ports:
    - port: 6379
      targetPort: 6379
```

Note: No PVC is needed — Redis is used as a broker only; job state is persisted in PostgreSQL (this is an explicit out-of-scope decision per REQUIREMENTS.md).

Note: The `commonLabels` in `kustomization.yaml` applies `app: meal-plan-analyzer` to all resources in the base. This conflicts with the Redis selector `app: redis`. To prevent kustomize from overriding the Redis pod selector, do NOT add `app: redis` labels manually — kustomize will inject `app: meal-plan-analyzer` as an additional label. The selector `matchLabels` must use `app: meal-plan-analyzer` too, or the Deployment will be broken. However, since `commonLabels` patches all selectors, kustomize handles this consistently. Leave the selectors and labels as `app: redis` in the raw manifest — kustomize's `commonLabels` will add `app: meal-plan-analyzer` on top but the selector will be patched by kustomize to match. Actually, the safest approach: omit `app: redis` labels entirely and let kustomize's `commonLabels: app: meal-plan-analyzer` handle labeling uniformly. Use `app: redis` only for human-readable context in names, not in selectors. For correctness, set selector `matchLabels: app: redis` and pod labels `app: redis` — kustomize `commonLabels` will ADD `app: meal-plan-analyzer` alongside `app: redis` in both the selector and labels, keeping them consistent.
