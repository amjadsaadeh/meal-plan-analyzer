The complete updated file should be:

```yaml
  DEBUG: "False"
  ALLOWED_HOSTS: "*"

  REDIS_URL: "redis://redis:6379/1"
  SITE_BASE_URL: "http://localhost:8000"
```

Note on `SITE_BASE_URL`: In k8s, the Celery worker is a sidecar in the same pod as the web container. The worker reaches the web server via `http://localhost:8000` (same pod, shared network namespace). This differs from Docker Compose where it was `http://web:8000`.

Note on Redis hostnames: In k8s, the Redis Service is named `redis` (ClusterIP). The hostname `redis` resolves within the cluster namespace. DB 0 is the Celery broker; DB 1 is the Django cache backend (set in Phase 1 via `REDIS_URL` / `CELERY_BACKEND_URL`).

<task type="auto">
  <name>Task 2: Add Celery worker sidecar to Deployment</name>
  <files>deployment/app-deployment/k8s/base/deployment.yaml</files>
  <action>
Add a `worker` container to the `containers` list in `deployment/app-deployment/k8s/base/deployment.yaml`.

The worker sidecar must be placed after the existing `meal-plan-analyzer` container. Add this container spec:

```yaml
        - name: worker
          image: image_name
          imagePullPolicy: Always
          command:
            - celery
            - -A
            - config
            - worker
            - --loglevel=info
            - --concurrency=2
            - --max-tasks-per-child=50
          envFrom:
            - configMapRef:
                name: meal-plan-analyzer-config
            - secretRef:
                name: meal-plan-analyzer-secret
          volumeMounts:
            - name: media
              mountPath: /app/media
```

Key constraints:
- Use `image: image_name` (same placeholder as the web container — kustomize overlays replace this with the actual image tag)
- `envFrom` must reference the same `configMapRef` and `secretRef` as the web container — the worker needs `DATABASE_URL`, `SECRET_KEY`, `CELERY_BROKER_URL`, `REDIS_URL`, etc.
- Mount only `media` volume (not `staticfiles` or `sass-cache` — the worker generates PDFs and writes them to media, it does not serve static files)
- No `ports` section — the worker does not expose any network ports
- No `livenessProbe` or `readinessProbe` — Celery workers are managed by Celery's own health checks; adding k8s probes here would require a custom probe command and is out of scope

The resulting `containers` list will have two entries: `meal-plan-analyzer` (web) and `worker` (Celery sidecar).
  </action>
